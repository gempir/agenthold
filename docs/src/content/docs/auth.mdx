Users sign in through an external identity provider, or as the single **local admin** defined in the server
config file (path in `AGENTHOLD_CONFIG`, YAML, `${VAR}` and `${VAR:-default}` references are expanded from the
environment; `$` without braces is kept as is). There is no signup and there are no other passwords.

Supported provider types:

- `oidc`: any OpenID Connect provider (Keycloak, Authentik, Okta, Google, ...). See [Keycloak and OIDC](/auth-keycloak/).
- `github`: GitHub or GitHub Enterprise Server via OAuth2. See [GitHub sign-in](/auth-github/).

## Local admin

For a single-user install, or to get in before an identity provider is set up, configure exactly one local
admin with a username and an argon2id password hash:

```sh
agenthold hash-password        # asks for the password twice (or reads one line from stdin)
```

```yaml
auth:
  local:
    username: admin
    password_hash: $argon2id$v=19$m=65536,t=3,p=4$...   # output of agenthold hash-password
```

The login page then shows a username and password form (`POST /api/v1/auth/local`). Wrong credentials and wrong
usernames take the same time to answer, and attempts are rate limited per client address (10 per 5 minutes) and
overall (60 per 5 minutes). Behind a reverse proxy the client address is the proxy's, so the per-client limit
applies to everyone together. The local admin is an ordinary user (identity provider `local`, subject = username)
with no email address, so other users cannot share agents with it by email. Changing the username creates a new
user.

If neither `auth.local` nor any provider is configured, nobody can sign in: the server still starts, logs a
warning that says what to add, and the login page says that sign-in is not set up. agenthold never generates
credentials.

## How sign-in works with a provider

1. The browser visits `/api/v1/auth/login/<provider id>`.
2. The server redirects to the provider (authorization code flow; OIDC uses PKCE).
3. The provider redirects back to `<public_url>/api/v1/auth/callback/<provider id>`.
4. The server exchanges the code, reads the user's identity and email, and starts a browser session.

An identity is stored as (provider `id`, subject). Changing a provider's `id` detaches existing users from it,
so pick it once. Accounts are never merged by email address: signing in with Keycloak and with GitHub
creates two separate users, because an email claim alone does not prove that both logins belong to the same person.

A user exists once they have signed in. Agents are shared by the email address a provider reported as
verified; see [Sharing and audit](/sharing/).

## Roles

Every user has one of three roles:

| Role | May |
| --- | --- |
| **Admin** | Everything: the **Overview** (every node, machine and user), nodes and join tokens, picking the node of a new agent, the Slack connection, role overrides, and all a User may, with no agent limit. |
| **User** | Use the agents it owns and the ones shared with it (chats, prompts, terminal, files) and create its own agents, up to `auth.user_max_agents` (default 2; templates and clones count). |
| **Disabled** | Nothing. The user can sign in, but sees *"Your account has no access to this agenthold"* and can only sign out. Every API call but `GET /me` and sign-in/out answers 403, its API tokens and Slack link do nothing, its schedules and webhooks do not run, and its agents get no platform tools. |

**New installs default to Disabled**: a person who signs in and matches no rule below gets no access until the
config or an admin gives them a role. Sharing does not change roles: a shared agent is usable by a User (and an
Admin), not by a Disabled user.

### Where a role comes from

The rules, in order; the first that applies decides:

1. The **local admin** (`auth.local`) is always Admin. No override applies to it.
2. An admin's **override** for the user (Overview, *Users*), if one is set.
3. A verified e-mail address listed in **`auth.admins`**: Admin.
4. The **provider's mapping**:
   - GitHub: `github_roles` by numeric user id, else an id in `github_allowed_ids` gets User
     ([GitHub sign-in](/auth-github/)).
   - OIDC: `role_attribute_path`, a JMESPath expression over the ID token and userinfo claims, like Grafana's
     ([Keycloak and OIDC](/auth-keycloak/)).
5. **Nothing matched**: a strict provider refuses the sign-in (no user is created): an OIDC provider with
   `role_attribute_strict: true`, or a GitHub provider with a non-empty `github_allowed_ids` (as before roles
   existed). Otherwise the user gets the provider's `default_role`, else `auth.default_role` (default `disabled`).

The role is evaluated at **every sign-in** and stored with the user. It is also re-evaluated for every user when
the server **starts**, so removing someone from `auth.admins` or `github_roles` takes effect with the restart that
loads the new config, not at their next sign-in. OIDC claims are not stored: at a start the result of the user's
last `role_attribute_path` evaluation is reused, and a role removed in the identity provider applies at the
user's next sign-in. agenthold keeps its own session and does not refresh provider tokens, so to cut somebody off
at once, set an override to **Disabled** in the Overview.

The role is read from the database on every request: a change (sign-in, restart or override) applies to the
user's existing sessions and API tokens immediately.

### Overrides

Admins see a **Users** list at the bottom of the Overview with each user's provider, agent count, last sign-in,
the role configuration gives them and an override select (`PUT /api/v1/admin/users/{id}/role`, body
`{"override": "admin" | "user" | "disabled" | null}`). An override wins over configuration until it is cleared
(*From configuration*), and it also lets a user in whom a strict provider would refuse. Admins cannot change
their own role (another admin can) or the local admin's, so an installation cannot lose its last admin by
accident. Overrides exist because identity-provider changes only apply at the next sign-in and config changes
need a restart; they are logged, and the config file stays the place for durable rules.

```yaml
auth:
  default_role: disabled        # admin | user | disabled (any case); default disabled
  user_max_agents: 2            # agents a User may own, templates and clones included; default 2, 0 = none
  admins: [ops@example.com]     # verified e-mail addresses that get Admin
```

## Sessions

Sessions are cookie based and expire after `session_ttl` without use (default `720h`, 30 days). With an https
`public_url` the cookie is `__Host-agenthold_session` (host-only, Secure, Path=/), which no other host can set or
shadow; over http (development) it is `agenthold_session`. A request with two session cookies is refused.

## Config reference

```yaml
listen: ":8080"                    # default :8080
public_url: https://agenthold.example.com   # default http://localhost:8080; used to build callback URLs
data_dir: /data                    # default ./data
auth:
  session_ttl: 720h                # Go duration, default 30 days
  default_role: disabled           # role when no rule matches: admin | user | disabled
  user_max_agents: 2               # agents a User may own (Admins: no limit)
  admins: []                       # verified e-mails that get the Admin role
  local:                           # optional, the one local admin
    username: admin
    password_hash: $argon2id$...   # from agenthold hash-password
  providers:
    - id: keycloak                 # URL path segment, unique, no / ? #
      type: oidc                   # oidc | github
      name: Keycloak               # label on the login button, defaults to id
      client_id: agenthold         # required
      client_secret: ${KC_SECRET}
      scopes: [openid, profile, email]   # optional, see defaults below
      issuer: https://sso.example.com/realms/main   # oidc, required
      discovery_url: ""            # oidc, optional
      role_attribute_path: ""      # oidc, optional JMESPath returning Admin | User | Disabled
      role_attribute_strict: false # oidc, refuse sign-in when the path yields no role
      default_role: ""             # optional, overrides auth.default_role for this provider
      github_url: ""               # github, optional
      github_api_url: ""           # github, optional
      github_allowed_ids: []       # github, optional numeric ids: at least User; others refused
      github_roles: {}             # github, optional {admin: [ids], user: [ids], disabled: [ids]}
preview:
  host_suffix: ""                  # e.g. .apps.example.com; empty = preview URLs off, see Preview URLs
```

| Field | Types | Notes |
| --- | --- | --- |
| `id` | all | Used in `/api/v1/auth/login/{id}` and the callback URL. `local` is reserved. |
| `type` | all | `oidc` or `github`. |
| `name` | all | Display name. |
| `client_id`, `client_secret` | all | From the provider. Use `${ENV}` for the secret. |
| `scopes` | all | Default `openid profile email` (oidc), `read:user user:email` (github). |
| `issuer` | oidc | Must match the `iss` claim in ID tokens exactly. |
| `discovery_url` | oidc | Base URL to fetch `/.well-known/openid-configuration` from, when the server cannot reach `issuer`. |
| `github_url` | github | Default `https://github.com`. |
| `github_api_url` | github | Default `https://api.github.com`. |
| `role_attribute_path` | oidc | JMESPath over the ID token claims, then the userinfo claims; must return `Admin`, `User` or `Disabled` (any case). Checked at startup. |
| `role_attribute_strict` | oidc | Refuse sign-in when `role_attribute_path` yields no valid role. Needs `role_attribute_path`. |
| `default_role` | all | Role for this provider's users no rule matches. Default `auth.default_role`. |
| `github_allowed_ids` | github | Numeric user ids that may sign in, with at least the User role. Non-empty means: others are refused. |
| `github_roles` | github | Numeric user ids per role. Listed ids may sign in even if `github_allowed_ids` omits them. An id may be in one role only. |

Environment overrides: `AGENTHOLD_LISTEN`, `AGENTHOLD_PUBLIC_URL`, `AGENTHOLD_DATA_DIR`, `AGENTHOLD_DEV_PROXY`,
`AGENTHOLD_PREVIEW_HOST_SUFFIX`. `preview.host_suffix` is described in [Preview URLs](/previews/).

Unknown YAML keys are rejected at startup. Set `public_url` to the exact URL users open in the browser,
otherwise the redirect URI will not match what you registered with the provider.
