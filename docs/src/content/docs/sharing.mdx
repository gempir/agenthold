## Who can do what

Every agent has one **owner**: the user who created it. The owner can share the agent with other users. There
are no workspaces, teams or role levels; for any agent, a user is one of:

| Relation | Can |
| --- | --- |
| owner | everything: use the agent, change its settings, harness, tools, secrets, schedules and webhooks, run harness logins, make it use their own provider logins, share and unshare it, read the audit log, reset its system and delete it |
| shared user | use the agent: read sessions (live) and files, create sessions, prompt, cancel, open terminals, change files, start and stop it, see who it is shared with, run schedules, leave |
| anyone else | nothing; the agent does not exist for them (API requests about it return 404) |

All checks are made on the server, in `internal/authz`. The UI only hides what a user cannot do.

## Sharing an agent

The owner shares an agent on its **Sharing** tab (or `POST /api/v1/agents/{id}/shares` with `{"email": ...}`)
by entering the other user's email address. A user exists once they have signed in, and they are found by the
email their identity provider reported **as verified**. If several accounts use the same verified email (for
example the same person signed in with Keycloak and with GitHub), sharing by that email is refused as ambiguous.

The owner removes a share on the same tab; a shared user can remove themselves ("Leave"). Losing access takes
effect at once, including for live session streams.

Shared users have a terminal, so they can read everything inside the sandbox, including a harness login made
there. They never see secret values or the owner's provider login credentials: those stay on the server.
They do act with them, though: the agent's requests carry the owner's secrets and the owner's
[git and GitHub credentials](/git/#who-can-use-your-credentials), so a shared user can have it push or open pull
requests as the owner.

## Provider logins of shared agents

An agent uses the Claude Code or Codex login of its owner by default, shown on its Overview. Users the agent is
shared with use that login through it. Nobody can make an agent use another person's login: only the owner
chooses, and only their own. See [sessions and harnesses](/sessions/#account-logins-the-normal-way).

## Watching together

Any number of people with access can watch a session live. The stream shows everyone who is watching, as
`owner` or `shared`. Every prompt in the log names the user who sent it.

## Audit log

The owner sees an agent's **Activity** tab: who did what, and when. It records prompts (with the prompt text),
cancels, permission answers, sessions created and deleted, terminals opened, harness logins, provider logins
attached, detached and used, file uploads, folders and deletions, starts, stops, system resets, setting changes,
secrets attached and detached, MCP servers and skills attached and detached, shares added and removed, and
deletions.
