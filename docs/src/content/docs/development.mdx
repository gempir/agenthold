---
title: "Development"
description: "Develop the native server in a Lima VM with nested virtualization."
---

On macOS, Firecracker development requires an Apple M3 or newer, macOS 15 or newer and
[Lima](https://lima-vm.io) (`brew install lima`). The template uses `vmType: vz` and nested virtualization;
OrbStack does not provide `/dev/kvm`. Install Bun 1.4.5 on the Mac for the embedded web build.

```sh
make dev-vm                         # create/start the VM
make runtime guest-kernel guest-base # prepare binaries, kernel and base disk
make dev                            # build web, run native server with live reload
```

The first guest builds can take substantial time and disk space. `make dev` serves the built web app at
http://localhost:8080 and restarts the Go server when its source changes. Run `make web` again for UI changes;
rebuild the base with `make guest-base` when changing guest contents (`images/base`). sandboxd is not in the base, and it
is not a separate program: the driver delivers the server's own (static Linux) binary at every boot, so a
restarted machine runs the rebuilt one. `sandbox.sandboxd_path` can name another agenthold build. The development-only local
administrator is `admin` / `admin` in `deploy/dev/agenthold.yaml`; do not use those credentials elsewhere.

The VM mounts only the checkout it was created from (`make dev-vm` creates it, and it keeps that path). Guest
and release scripts re-run inside the VM at the same path as on the Mac, so run them from that checkout. A
second `git worktree` is not mounted; copy it into the VM or create another VM from it. A release build is
`VERSION=v0.1.0 scripts/release/build.sh` (or `VERSION=sha-$(git rev-parse HEAD)` for a `main` commit) after
`make web`; see [deployment](/deploy/).

`make dev-vm-shell` opens a shell in the checkout inside the VM; `make dev-vm-delete` removes the VM. The
checkout is writable through virtiofs, port 8080 is forwarded, and guest listeners stay inside the VM.
The template installs Go, nftables and build tools and fails its startup probe if `/dev/kvm` is missing.

```sh
make test             # Go and web tests without KVM
make test-kvm         # KVM-tagged tests (root in the Linux VM)
make test-guest       # boot guest, exercise tunnel and persistent disks
scripts/e2e/edge.sh   # controller without a local node + Firecracker edge node (in the VM)
make lint
make build
```

`make test-go` runs the API suite twice: once against the in-process node and once with
`AGENTHOLD_TEST_NODE=remote`, where the same fake node joins over TLS as an [edge node](/edge-nodes/).
`scripts/e2e/edge.sh` builds the binaries, runs a controller with `sandbox.driver: none` and a Firecracker
node in its own network namespace inside the Lima VM, and drives threads, terminal, files, sleep/wake, a node
outage and secret injection through the API (it needs internet access for an HTTPS echo service).

The fake driver runs sandbox processes on the host and is for tests and UI development only. For browser
smoke tests configure `sandbox.driver: fake` on a development-only server, build `agenthold` and `fakeagent`
next to each other (the server's directory is where the fake harness is looked for), and enable `test_harness`. Then run
`cd web && bun run e2e`; `E2E_USER`, `E2E_PASSWORD` and `BASE_URL` override the local defaults. Never use the
fake driver to isolate untrusted agents.

See [guest artifacts](/guest-artifacts/) for kernel and rootfs build details. The historical KVM spike is
`scripts/spike/firecracker.sh`.
