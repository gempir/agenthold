---
title: "Host hardening"
description: "Protect the Linux host that runs agenthold microVMs."
---

Each agent runs in a Firecracker microVM with a separate guest kernel, disks and network interface. The
jailer and host firewall provide additional boundaries. These do not make the host or operator untrusted;
keep the host patched and restrict administrator access.

- Run on a dedicated Linux host with KVM and nftables. The node needs root for tap devices and jailer setup.
- Expose agenthold through your own HTTPS reverse proxy or tunnel. Restrict administrative services and do
  not expose the sandbox tunnel or proxy listeners to the internet.
- Back up the database, master key, CA and agent disks securely. Restrict access to the configuration and
  data directory.
- Do not place sensitive host services where guest traffic could reach them. Verify firewall behavior on your
  host after changing network configuration.
- Give agents only data they may send to public internet destinations. Secret injection limits where a
  credential is attached, but an agent can still send data it can read elsewhere.

See [security](/security/) for the trust model and limitations and [egress](/egress/) for traffic handling.
