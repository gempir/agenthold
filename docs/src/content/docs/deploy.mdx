Automatic demo deployment is disabled during the Firecracker transition. The replacement deployment for
`scarif.local` has not been configured; pushing to `main` does not deploy a server.

On a Linux KVM host, follow [Install](/install/), put the foreground service behind an HTTPS reverse proxy or
tunnel, and keep its configuration and data directory persistent. Upgrade by backing up the database, keys
and agent disks, stopping the service, replacing the binary and starting it again. The base disk is shared;
resetting an agent's system replaces its writable system overlay while preserving its home disk.

Native release assets, automated installation and rollback procedures will be documented with the release
workflow. Verify backups before upgrading.

## HTTPS examples

Choose one of these approaches. Each assumes agenthold listens on `127.0.0.1:8080` and
`public_url` is `https://agents.example.com`. Configure DNS and firewall access for your own host.

### Caddy

With DNS pointing to the proxy and ports 80 and 443 available, Caddy can obtain and renew a certificate.
Its reverse proxy handles WebSocket upgrades:

```caddy
agents.example.com {
  reverse_proxy 127.0.0.1:8080
}
```

See the [Caddy reverse proxy guide](https://caddyserver.com/docs/quick-starts/reverse-proxy).

### nginx

Place the `map` inside nginx's `http` block, and provide your own certificate and key:

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
server {
    listen 443 ssl;
    server_name agents.example.com;
    ssl_certificate /etc/ssl/agents/fullchain.pem;
    ssl_certificate_key /etc/ssl/agents/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600s;
    }
}
```

See [nginx WebSocket proxying](https://nginx.org/en/docs/http/websocket.html). Configure certificate
renewal and HTTP-to-HTTPS redirects separately.

### Cloudflare Tunnel

Create a tunnel and its DNS route in your Cloudflare account, then configure a locally managed `cloudflared`
tunnel with its credentials file:

```yaml
tunnel: YOUR_TUNNEL_ID
credentials-file: /etc/cloudflared/YOUR_TUNNEL_ID.json
ingress:
  - hostname: agents.example.com
    service: http://127.0.0.1:8080
  - service: http_status:404
```

Run `cloudflared` as a service using that configuration. See the [Cloudflare Tunnel configuration
reference](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/local-management/configuration-file/).
