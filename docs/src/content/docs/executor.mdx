---
title: "Accounts (Executor)"
description: "Connect external apps and accounts once with the built-in Executor runtime so your agents can use them safely over MCP."
---

agenthold ships with [Executor](https://executor.sh/docs) built directly into the main release binary to manage external apps, OAuth2 connections, API keys and MCP tools for every user.

## How it works

1. **One isolated Executor per user**: Each user gets their own private `executor serve --stdio` subprocess on the controller, with its own encrypted data directory (`<data_dir>/executor/users/<user_id>`), its own encryption key derived from the server master key, and its own loopback API key. Instances start lazily on first use and stop automatically after `executor.idle_timeout` (default `30m`) when no agent owned by that user is running.
2. **Credentials never enter sandboxes**: Agents never see `EXECUTOR_API_KEY` or any saved OAuth2 token, cookie or API key. Instead, every enabled agent automatically receives a built-in stdio MCP server named `executor` (`sandboxd executor-mcp`) that streams JSON-RPC over the authenticated agent tunnel to the controller, which forwards calls to the agent owner's Executor instance and logs tool invocations to the audit log.
3. **One place to manage accounts**: Open **Settings → Integrations → Connected accounts** (`/settings/accounts`) to install apps from the Executor catalog, import custom remote MCP servers, connect API-key/token accounts directly in agenthold, link or switch saved accounts per app requirement, and check credential health.

## Integrations settings

**Settings → Integrations** (`/settings/integrations`) gathers everything an agent can connect to, in four tabs. The older URLs still open the matching tab:

- **Organization**: tools and skills an admin set up for everyone. Tools with a shared organization credential (or none) show **Provided by organization** and need no setup; each user can switch them off for themselves. For tools where each user signs in with their own account, one **Connect** button installs the app and opens the sign-in, or shows an inline token form. Admins add, edit and delete organization tools and skills here.
- **Connected accounts** (`/settings/accounts`): your installed apps and saved accounts, with health checks and **Add integration** for the catalog. The Executor runtime starts on demand, so the page only shows a notice when Executor is turned off or unavailable on the server.
- **Git & GitHub** (`/settings/git`): commit identity, Connect GitHub and HTTPS credentials ([Git](/git/)).
- **Advanced** (`/settings/tools`): your own MCP servers and skills.

Organization provider logins (shared API keys, OAuth tokens or gateways for Claude Code, Codex, Antigravity and OpenCode) are listed under **Settings → Provider logins**. A personal login overrides the organization one.

## Requests from agents in the chat

Agents can ask for what they are missing without sending you to the settings:

- `request_secret` shows a secure card in the thread with the secret's name, why it is needed and the hosts it is sent to. **Save securely** stores the value encrypted in your secrets and activates it in the egress proxy; **Decline** refuses. The value never enters the conversation or the sandbox, and the card collapses to a one-line status once answered.
- `request_account_connect` shows a **Connect** card for an organization tool, which runs the same one-click connect as the Integrations page.

## OAuth2 and the Executor dashboard

When `preview.host_suffix` is configured (or `executor.public_url` is set explicitly), agenthold automatically serves the full Executor dashboard at `executor<preview.host_suffix>` (for example, `https://executor-demo.agenthold.dev`), protected by agenthold's own session authentication with automatic server-side pairing — no separate Executor pairing prompt is shown.

- Over **HTTPS**, OAuth2 provider sign-in flows (Google, GitHub, Slack, Linear, Notion, etc.), `/account-connect/:id` links generated by agents, and browser-based tool approval links work end to end.
- Without a wildcard preview domain or HTTPS (for example, local `http://localhost:8080` development), **Settings → Integrations → Connected accounts** still supports installing catalog apps, importing custom MCP servers, and connecting secret/API-key accounts natively.

## Per-agent settings

Open an agent's **Settings → Tools** tab to control how that agent uses Executor:

- **Enable Executor MCP server** (disabled by default): opt in per agent to expose the built-in `executor` MCP server on the agent's next session. Sharing an agent with another user automatically turns Executor off so collaborators never silently gain access to your connected accounts; you can explicitly re-enable it afterward if intended.
- **Tool approval mode**:
  - `model` (default): when an Executor tool requires approval, Executor asks the agent to confirm with you in chat and resume.
  - `automatic`: Executor approves immediately; the agent harness's own tool-confirmation policy guards tool calls.
  - `browser`: Executor pauses the tool call and returns a signed-in approval link on your Executor dashboard host.

Standalone [apps](/apps) never receive Executor access.

## Configuration

Executor works out of the box in release builds with zero configuration. Optional `executor:` settings in `config.yaml`:

```yaml
executor:
  # Disable the built-in Executor runtime entirely.
  disabled: false
  # Override the Executor binary path (default: bundled runtime or PATH).
  binary: ""
  # Explicit public HTTPS origin for the Executor dashboard and OAuth2 callbacks.
  # Defaults to https://executor<preview.host_suffix> when preview.host_suffix is set.
  public_url: ""
  # Stop idle per-user Executor instances after this duration (default 30m).
  idle_timeout: 30m
  # Allow importing custom MCP servers and deploying custom apps (default false).
  # Official catalog apps work with this false; enable only if you trust users
  # to configure arbitrary endpoints reachable from the controller's network.
  allow_private_fetch: false
```

For local development (`make dev` inside the Linux Lima VM), run `make runtime` or `make executor-runtime` to fetch the Linux Executor runtime into `build/runtime/executor-linux-<arch>`. When running `go run ./cmd/agenthold` directly on macOS, run `./scripts/guest/fetch-executor.sh` (or install `executor` on your `PATH`, or set `AGENTHOLD_EXECUTOR_BINARY`).
