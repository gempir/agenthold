---
title: "Preview URLs"
description: "Expose ports of a machine over HTTP at their own hostname, behind the agenthold sign-in or in public."
---

A machine can expose any TCP port its software listens on. Each exposure gets its own hostname,
`<name><preview.host_suffix>`, for example `todo-3000.apps.example.com`. agenthold routes the request by its
`Host` header, connects to the port inside the microVM through the machine's tunnel (this works for machines on
[edge nodes](/edge-nodes/) too) and proxies HTTP, streaming responses and WebSockets.

A sleeping machine wakes up on the first request. A browser sees a short "Waking up" page that reloads itself
while it boots; other clients get `503` with `Retry-After`. Requests to an exposure count as activity, so a
machine being browsed does not fall asleep.

## Turn it on

Preview URLs are off until you set a host suffix:

```yaml
public_url: https://agents.example.com
preview:
  host_suffix: .apps.example.com   # or AGENTHOLD_PREVIEW_HOST_SUFFIX
```

The suffix starts with `.` or `-`:

| Suffix | Exposure `web` | Certificate you need |
| --- | --- | --- |
| `.apps.example.com` | `web.apps.example.com` | `*.apps.example.com` |
| `-demo.example.com` | `web-demo.example.com` | `*.example.com` (names stay one label below the domain) |

The `-` form is for providers whose free wildcard certificates cover only one level below the domain
(Cloudflare's universal certificate, for example). The main host must not end with the suffix, and names are
1 to 40 lowercase letters, digits and hyphens.

Then point a wildcard DNS record at the same reverse proxy that serves agenthold and forward the hosts to the
same `listen` address. agenthold still terminates no TLS: exposures use the scheme and port of `public_url`.

### Caddy

A wildcard certificate needs the DNS challenge, so build Caddy with your DNS provider's module:

```caddy
agents.example.com, *.apps.example.com {
  tls {
    dns cloudflare {env.CF_API_TOKEN}
  }
  reverse_proxy 127.0.0.1:8080
}
```

### Cloudflare Tunnel

Add a wildcard DNS record (`*.apps` or, for the `-` form, `*`) as a CNAME to `YOUR_TUNNEL_ID.cfargotunnel.com`
and a wildcard ingress rule:

```yaml
ingress:
  - hostname: agents.example.com
    service: http://127.0.0.1:8080
  - hostname: "*.apps.example.com"
    service: http://127.0.0.1:8080
  - service: http_status:404
```

## Expose a port

- In the UI: agent settings, **Preview**. The owner exposes a port, picks the name and access, changes access
  and removes exposures. Shared users see the links.
- Over the API: `GET`/`POST /api/v1/agents/{id}/exposures`, `PATCH`/`DELETE /api/v1/agents/{id}/exposures/{exposureId}`
  (owner only for changes). Every change is in the agent's audit log.
- From inside the machine: the agent's platform tools `expose_port(port, name?, access?)`, `list_exposures()` and
  `unexpose(port)` act on the agent's own machine. An agent can create `private` and `authenticated` exposures;
  only the owner can make one `public`.

The server must listen on the machine's loopback (`127.0.0.1` or `::1`); `python3 -m http.server 8000` works as is.
When nothing listens on the port, visitors get `502 Nothing is listening on port N`.

## Access

| Access | Who gets in |
| --- | --- |
| `private` (default) | the machine's owner and the users it is shared with |
| `authenticated` | anyone signed in to this agenthold |
| `public` | anyone; no identity is passed on |

Access is checked on every request: unsharing a machine or tightening access applies at once.

For `private` and `authenticated` exposures agenthold is the sign-in gate:

1. A browser without a preview cookie is redirected to `<public_url>/api/v1/preview/authorize?host=...&return=/path`.
2. The main host asks for the normal sign-in if needed, checks access, and redirects back to
   `https://<exposure host>/_agenthold/callback` with a single-use code that is valid for 60 seconds and only for
   that host.
3. The exposure host exchanges the code and sets its own host-only cookie (`__Host-ah_preview` over https,
   `ah_preview` over http; HttpOnly, SameSite=Lax), valid for 24 hours, then returns to the path. Only paths are
   accepted as return targets.

Requests without a cookie that are not page loads (API calls, `fetch`) get `401` JSON instead of a redirect.
Scripts can send an agenthold API token as `Authorization: Bearer ahp_...`; it is removed before the request
reaches the app. `/_agenthold/logout` on an exposure host ends its preview session. Paths under `/_agenthold/`
are reserved.

## Identity headers

agenthold removes every incoming `X-Agenthold-*` header and its own cookies before proxying. For `private` and
`authenticated` exposures it then sets:

| Header | Value |
| --- | --- |
| `X-Agenthold-User` | the user id |
| `X-Agenthold-Email` | the user's email (may be empty) |
| `X-Agenthold-Name` | the display name |
| `X-Agenthold-Identity` | a JWT (EdDSA, Ed25519) valid for 5 minutes: `sub`, `email`, `name`, `aud` = the exposure host, `iss` = `public_url` |

The plain headers are fine for an app that is only reachable through agenthold. To be sure a request came
through agenthold, verify the JWT with the keys at `<public_url>/.well-known/agenthold/jwks.json`:

```js
import { createRemoteJWKSet, jwtVerify } from "jose";

const jwks = createRemoteJWKSet(new URL("https://agents.example.com/.well-known/agenthold/jwks.json"));

export async function user(req) {
  const { payload } = await jwtVerify(req.headers["x-agenthold-identity"], jwks, {
    issuer: "https://agents.example.com",
    audience: "todo-3000.apps.example.com",
    algorithms: ["EdDSA"],
  });
  return { id: payload.sub, email: payload.email, name: payload.name };
}
```

The signing key is generated on first start at `<data_dir>/preview/identity.key`. Back it up with the rest of
the data directory; a new key only means apps fetch the new JWKS.

## Security notes

- Exposure hosts never reach the agenthold API or web app: the router answers them before the API, and the
  main session cookie is host-only, so browsers never send it to exposure hosts.
- An app's `Set-Cookie` headers lose their `Domain` attribute, so one exposure cannot set cookies for its
  siblings through the server. Exposures still share a site with each other (and with the main host if they share
  a registrable domain); treat apps on the same suffix as able to make same-site requests to each other.
- The tunnel only connects to the machine's loopback interface.
- Machines whose guest image predates preview URLs answer with an error until they restart on a current base
  image.
