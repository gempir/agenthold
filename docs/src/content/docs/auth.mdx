Users sign in through an external identity provider, or as the single **local admin** defined in the server
config file (path in `AGENTHOLD_CONFIG`, YAML, `${VAR}` and `${VAR:-default}` references are expanded from the
environment; `$` without braces is kept as is). There is no signup and there are no other passwords.

Supported provider types:

- `oidc`: any OpenID Connect provider (Keycloak, Authentik, Okta, Google, ...). See [Keycloak and OIDC](/auth-keycloak/).
- `github`: GitHub or GitHub Enterprise Server via OAuth2. See [GitHub sign-in](/auth-github/).

## Local admin

For a single-user install, or to get in before an identity provider is set up, configure exactly one local
admin with a username and an argon2id password hash:

```sh
agenthold hash-password        # asks for the password twice (or reads one line from stdin)
```

```yaml
auth:
  local:
    username: admin
    password_hash: $argon2id$v=19$m=65536,t=3,p=4$...   # output of agenthold hash-password
```

The login page then shows a username and password form (`POST /api/v1/auth/local`). Wrong credentials and wrong
usernames take the same time to answer, and attempts are rate limited per client address (10 per 5 minutes) and
overall (60 per 5 minutes). Behind a reverse proxy the client address is the proxy's, so the per-client limit
applies to everyone together. The local admin is an ordinary user (identity provider `local`, subject = username)
with no email address, so other users cannot share agents with it by email. Changing the username creates a new
user.

If neither `auth.local` nor any provider is configured, nobody can sign in: the server still starts, logs a
warning that says what to add, and the login page says that sign-in is not set up. agenthold never generates
credentials.

## How sign-in works with a provider

1. The browser visits `/api/v1/auth/login/<provider id>`.
2. The server redirects to the provider (authorization code flow; OIDC uses PKCE).
3. The provider redirects back to `<public_url>/api/v1/auth/callback/<provider id>`.
4. The server exchanges the code, reads the user's identity and email, and starts a browser session.

An identity is stored as (provider `id`, subject). Changing a provider's `id` detaches existing users from it,
so pick it once. Accounts are never merged by email address: signing in with Keycloak and with GitHub
creates two separate users, because an email claim alone does not prove that both logins belong to the same person.

A user exists once they have signed in. Agents are shared by the email address a provider reported as
verified; see [Sharing and audit](/sharing/).

## Sessions

Sessions are cookie based and expire after `session_ttl` without use (default `720h`, 30 days).

## Config reference

```yaml
listen: ":8080"                    # default :8080
public_url: https://agenthold.example.com   # default http://localhost:8080; used to build callback URLs
data_dir: /data                    # default ./data
auth:
  session_ttl: 720h                # Go duration, default 30 days
  local:                           # optional, the one local admin
    username: admin
    password_hash: $argon2id$...   # from agenthold hash-password
  providers:
    - id: keycloak                 # URL path segment, unique, no / ? #
      type: oidc                   # oidc | github
      name: Keycloak               # label on the login button, defaults to id
      client_id: agenthold         # required
      client_secret: ${KC_SECRET}
      scopes: [openid, profile, email]   # optional, see defaults below
      issuer: https://sso.example.com/realms/main   # oidc, required
      discovery_url: ""            # oidc, optional
      github_url: ""               # github, optional
      github_api_url: ""           # github, optional
```

| Field | Types | Notes |
| --- | --- | --- |
| `id` | all | Used in `/api/v1/auth/login/{id}` and the callback URL. `local` is reserved. |
| `type` | all | `oidc` or `github`. |
| `name` | all | Display name. |
| `client_id`, `client_secret` | all | From the provider. Use `${ENV}` for the secret. |
| `scopes` | all | Default `openid profile email` (oidc), `read:user user:email` (github). |
| `issuer` | oidc | Must match the `iss` claim in ID tokens exactly. |
| `discovery_url` | oidc | Base URL to fetch `/.well-known/openid-configuration` from, when the server cannot reach `issuer`. |
| `github_url` | github | Default `https://github.com`. |
| `github_api_url` | github | Default `https://api.github.com`. |

Environment overrides: `AGENTHOLD_LISTEN`, `AGENTHOLD_PUBLIC_URL`, `AGENTHOLD_DATA_DIR`, `AGENTHOLD_DEV_PROXY`.

Unknown YAML keys are rejected at startup. Set `public_url` to the exact URL users open in the browser,
otherwise the redirect URI will not match what you registered with the provider.
